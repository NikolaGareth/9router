# README 精简设计

## 目标

将中文 README 从约 1285 行精简到约 200 行，使项目首页能够快速说明 9Router 的用途，并覆盖安装、常用客户端接入、服务器部署和常用 API。

## 修改范围

- 同步修改根目录 `README.md` 与 `i18n/README.zh-CN.md`。
- 两份文档正文保持一致，仅本地图片和文件链接根据所在目录使用正确的相对路径。
- 不修改应用代码、配置格式、接口行为或部署脚本。

## 文档结构

1. 项目标题、简短定位和状态徽章。
2. 核心功能：统一 OpenAI 兼容接口、多提供商路由、自动回退、多账户、配额追踪和请求日志。
3. 快速开始：npm 全局安装、启动、Dashboard 地址和 API 基础地址。
4. 常用客户端配置：Claude Code、Codex CLI 和通用 OpenAI 兼容客户端。
5. 部署：VPS/systemd、Docker、必要环境变量和数据目录。
6. 常用 API：`GET /v1/models`、`POST /v1/chat/completions` 和 Bearer Key 鉴权。
7. 简短故障排查：服务未监听、鉴权失败、上游不可用和查看日志。
8. 项目链接与 MIT 许可证。

## 删除内容

- CLI 工具和提供商的大型图片表格。
- 时效性较强的价格、额度和“免费无限”宣传。
- 详细定价解释及成本案例。
- 多个使用案例和重复 FAQ。
- 逐提供商 OAuth/API Key 接入教程。
- 组合策略示例、完整模型清单和高级请求处理细节。
- 技术栈、云端同步、贡献者图片、Star 图表、分支和致谢章节。

## 内容原则

- 所有命令必须与当前项目脚本和默认端口一致。
- 不写入真实 API Key、密码、Cookie、内网地址或个人信息。
- 避免“永久免费”“无限使用”等不可长期验证的表述。
- 主要操作在首次阅读时即可找到，不依赖外部文档才能完成基础部署。
- 外部链接仅保留项目主页、npm 和仓库链接；内部相对链接必须存在。

## 验收标准

- 每份 README 目标为 180～230 行；为保证完整命令块，最多不超过 260 行。
- 根目录与中文源文件的章节、文字和代码示例一致。
- 本地图片和相对文件链接全部存在。
- Markdown 代码围栏成对，标题层级连续，无失效章节锚点。
- `git diff --check` 无新增格式错误。
- README 中不存在已删除的视频教程内容和其他语言 README 导航。
